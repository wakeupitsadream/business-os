## Что это
**Business OS** — персональный «пульт бизнес-жизни» владельца (Максим, он же
владелец SaaS Agentus). Один пользователь, десктоп + веб с телефона. Четыре
«отдела»-командных центра: **Секретарь**, **Финансы**, **Продажи** и
**Разработка** (последний — фаза 2 продукта).

Это НЕ Agentus и не его часть. Общего кода нет; переиспользуются только
проверенные инфраструктурные паттерны (см. ниже).

**Полный план — `PLAN.md`.** Читай его первым при любом содержательном вопросе:
там канонические решения, схемы данных всех модулей, дорожная карта по PR-ам с
Definition of Done и чек-лист ручных шагов владельца.

## Стек
Next.js 15 (App Router, `output: "standalone"`) + React 19 + TypeScript strict +
Prisma 6 + **Neon** (serverless PostgreSQL 16 + pgvector) + Tailwind v4 + Zod 4.
Авторизация — argon2id-пароль + JWT-кука (jose), один владелец. Тесты — vitest.
Десктоп — Tauri v2 (тонкая обёртка на прод-URL, фаза 4).

LLM — свой мультишлюз: каскад **Polza → ProxyAPI** (OpenAI-совместимые
`/chat/completions`, вызываются обычным `fetch`, без openai SDK). Роли-пресеты:
`smart` (Claude Sonnet), `heavy` (Opus), `cheap` (классификация/парсинг),
`embed` (1536).

## Инфраструктура (важно)
- Прод: **Timeweb App Platform**, один Docker-контейнер. Мёрж в `main` = релиз.
- БД **Neon**: две строки подключения — pooled (`-pooler`, PgBouncer) в
  `DATABASE_URL` для приложения и прямая в `DIRECT_URL` для миграций.
  Расширение включается миграцией `CREATE EXTENSION IF NOT EXISTS vector`.
  Scale-to-zero отключён: минутный крон и вебхуки не должны ждать пробуждения БД.
- **Кроны — встроенный планировщик контейнера** (`scripts/start-container.mjs`
  дёргает `/api/cron/*` по расписанию UTC с `CRON_SECRET`). Отдельного
  воркера/Redis нет и не планируется: один контейнер, один пользователь.
- **Telegram — только через прокси** (Cloudflare Worker, env
  `TELEGRAM_API_BASE`): прямой `api.telegram.org` из Timeweb заблокирован.
  Вебхук ставится на Worker (`TELEGRAM_WEBHOOK_BASE`), он форвардит на прод —
  прямая доставка Telegram → РФ-хостинг ретраится минутами.
- `/api/health` всегда отвечает 200 (liveness, не readiness): статус БД — в теле.
  Docker HEALTHCHECK делает `curl` **без** `-f`, иначе 503 при лежащей БД
  заставляет хостинг откатить деплой. Проба БД идёт только по `Bearer
  CRON_SECRET` или из сессии владельца, и в теле — категория отказа, а не текст
  ошибки Prisma (в нём хост и порт Neon). Проба живости — отдельный
  `/api/health/live`, без базы.

## Как работать в этом репозитории
1. Правь код → ветка `claude/<тема>` → push → зелёный CI → PR → мёрж.
   Прямой push в `main` не делай: это деплой в прод.
2. Перед пушем: `npm run typecheck && npm test` — должно быть зелено.
3. Каждый найденный баг → регрессионный тест. Без теста баг не закрыт.
4. Деньги — **всегда Int в копейках** (`@/core/shared/money`). Никаких float
   и Decimal: Decimal ломает сериализацию через границу Server Components.
5. Периоды бизнес-логики режутся по **Europe/Moscow**
   (`@/core/shared/time`), хранение — UTC. Операция в 02:00 МСК 1 августа по UTC
   ещё июльская — без этого месячные итоги не сходятся с выпиской.
6. Секреты не логировать и не коммитить. Логгер маскирует их сам, но не
   полагайся на это — не передавай их в логи вообще.
7. Новые зависимости — с осторожностью: `openai` SDK намеренно НЕ используется
   (конфликтует с Zod 4 и мешает мультишлюзовому каскаду).

## Ключевые директории (`src/`)
- `core/llm/` — мультишлюз, circuit-breaker, учёт `LlmUsage`, дневной бюджет
- `core/auth/` — пароль (argon2id), сессия (jose), rate-limit входа
- `core/telegram/` — клиент Bot API через прокси, разбор апдейтов, дедуп
- `core/cron/` — реестр и обработчики фоновых задач
- `core/shared/` — `money.ts` (копейки), `time.ts` (МСК), `cn.ts`
- `core/db.ts`, `core/env.ts`, `core/settings.ts`, `core/observability/logger.ts`
- `core/orchestrator/` — агентный цикл, реестр инструментов, подтверждения
- `core/memory/` — факты владельца: запись, векторный и словесный поиск
- `modules/secretary/` — Ася: промпт, инструменты, чек-ины, бриф, сводка дня
- `modules/finance/` — операции, категоризация по алиасам, метрики, периоды
- `modules/finance/import/` — разбор выписок: cp1251, CSV, парсеры банков,
  дедуп, переводы, коммит партии и откат
- `modules/finance/yookassa/` — синк поступлений: клиент, проводка, комиссия
- `modules/finance/insights/` — факты (только код) и формулировка карточек
- `app/(os)/` — командные центры отделов; `app/(auth)/login/` — вход
- `app/api/` — `health`, `cron/[job]`, `telegram/webhook`, `auth/*`,
  `chat`, `approvals/[id]`, `finance/transactions`
- `components/os/` — KpiCard, Sidebar, AgentStatus, Panel, EmptyState
- `components/finance/` — быстрый ввод, график, разбивка, режим приватности
- `middleware.ts` — периметр + режим техработ (работает при лежащей БД)

## Инварианты, которые нельзя ломать
- **Вебхук Telegram всегда отвечает 200** (кроме неверного секрета → 401):
  любой другой код заставляет Telegram ретраить апдейт бесконечно.
- **Дедуп вебхуков durable** (таблица `WebhookDedup`): in-memory недостаточно,
  контейнер перезапускается при каждом деплое.
- **Таймаут отправки НЕ ретраится**: запрос скорее всего доставлен, потерян
  только ответ — повтор дублирует сообщение владельцу.
- **Цифры считает код, LLM только интерпретирует.** Модель никогда не источник
  чисел на KPI-карточках и в отчётах.
- **Опасные действия агента** (внешняя отправка, необратимые операции с
  деньгами) не исполняются сразу — создают `Notification` с подтверждением.
  Флаг `dangerous` может быть предикатом от аргументов: расход на 300 ₽
  подтверждать незачем, на 300 000 ₽ — обязательно.
- **Деньги — целые копейки (Int)** во всей системе. Бизнес-периоды режутся по
  поясу владельца (`OWNER_TZ`, по умолчанию Asia/Yekaterinburg): операция
  1-го числа в 02:00 местного по UTC ещё в прошлом месяце. Пояс меняется
  переменной окружения, но расписание кронов в `scripts/start-container.mjs`
  задано в UTC и подобрано под него — сдвигать надо оба.
  Это же касается `buildDedupKey`: день в ключе московский, иначе одна и та же
  операция, выгруженная банком с временем и без, получает разные ключи.
- **Строки попадают в `Transaction` только через `createTransaction`.** У неё
  есть необязательный транзакционный клиент — именно им пользуется импорт,
  чтобы партия легла целиком или не легла вовсе.
- Миграции применяются на старте контейнера через `db-migrate-safe`: сбой
  ДОСТУПА к БД не валит деплой, настоящая ошибка миграции — валит.

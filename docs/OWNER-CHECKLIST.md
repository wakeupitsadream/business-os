# Что делает владелец руками

Один список всего, что нельзя сделать из кода. Порядок важен: приложение
узнаёт свой адрес только после создания в Timeweb, а Cloudflare Worker узнаёт
адрес приложения от вас.

Первый запуск — около получаса. **Собственный домен не нужен** ни для
приложения, ни для Telegram.

Подробности по каждому шагу — в [`DEPLOY.md`](./DEPLOY.md) и
[`../infra/cloudflare-worker/README.md`](../infra/cloudflare-worker/README.md).
Здесь — чек-лист, чтобы ничего не пропустить.

---

## Одна ошибка, которая роняет деплой

> **`DIRECT_URL` обязателен и обязан быть строкой БЕЗ `-pooler`.**
> Если его нет, миграции пойдут через пул, PgBouncer не пропустит блокировку
> Prisma, и контейнер не стартует вовсе. Это единственная ошибка в переменных,
> которая валит деплой целиком, — все остальные максимум оставят выключенной
> одну функцию.

## Запуск

### 1. База — Neon

- [ ] Создать проект, регион **eu-central**
- [ ] В SQL-консоли выполнить:
      ```sql
      CREATE EXTENSION IF NOT EXISTS vector;
      CREATE EXTENSION IF NOT EXISTS pg_trgm;
      ```
- [ ] Посмотреть **Usage**: сколько компьют-часов из лимита уже потрачено.
      На бесплатном тарифе их **100 в месяц и они общие на весь аккаунт** —
      делятся со всеми проектами, включая Agentus. Компьют-час считается в
      CU-часах: на минимальном размере 0.25 CU лимита хватает примерно на
      400 часов работы, то есть на 16 суток круглосуточной. Исчерпание
      останавливает **все** проекты аккаунта до следующего периода
- [ ] Scale-to-zero на Free отключить нельзя, и не надо: система не будит базу
      впустую — ни минутный крон напоминаний, ни проба живости контейнера
      (она ходит на `/api/health/live`, роут без базы). Если тариф платный —
      выключить в Settings → Compute
- [ ] Скопировать **две** строки подключения:
      - pooled (хост с `-pooler`), в конец дописать `&pgbouncer=true` → `DATABASE_URL`
      - direct (тот же хост без `-pooler`) → `DIRECT_URL`

### 2. Модель — Polza

- [ ] Получить `POLZA_API_KEY` на polza.ai
- [ ] **Пополнить баланс.** Без денег на счету не работает ничего из ИИ:
      ни чат, ни бриф, ни разбор незнакомой выписки
- [ ] *(по желанию)* ключ ProxyAPI и `LLM_GATEWAYS=polza,proxyapi` —
      см. «Резерва у модели нет» ниже

### 3. Секреты — локально

- [ ] `npm run hash:password -- 'ваш-пароль'` → `OWNER_PASSWORD_HASH`
      (в переменные идёт хэш, сам пароль нигде не хранится)
- [ ] `openssl rand -base64 48` → `AUTH_SECRET`
- [ ] `openssl rand -hex 32` → `CRON_SECRET`
- [ ] `openssl rand -hex 32` → `TELEGRAM_WEBHOOK_SECRET`

### 4. Бот — Telegram

- [ ] @BotFather → новый **личный** бот (не бот Agentus) → `TELEGRAM_BOT_TOKEN`
- [ ] @userinfobot → свой chat_id → `TELEGRAM_OWNER_CHAT_ID`

### 5. Приложение — Timeweb

- [ ] Создать приложение типа **Docker** из репозитория: ветка `main`,
      Dockerfile в корне, порт **3000**
- [ ] Вставить переменные окружения — блок целиком в [`DEPLOY.md` §3](./DEPLOY.md)
- [ ] Записать технический адрес приложения → `APP_URL`

Миграции контейнер применит сам при первом старте. Отдельно ничего запускать
не нужно.

### 6. Прокси Telegram — Cloudflare

Без него бот не сможет **отправлять** сообщения вообще: прямой
`api.telegram.org` из Timeweb заблокирован. Это не про скорость.

- [ ] Workers & Pages → Create → Worker с именем `telegram-proxy` → Deploy
- [ ] Edit code → вставить целиком `infra/cloudflare-worker/worker.js` → Deploy
- [ ] Settings → Variables and Secrets → добавить `ORIGIN` = адрес приложения
      из шага 5, **без слэша на конце**
- [ ] Записать выданный адрес `https://telegram-proxy.<аккаунт>.workers.dev`

### 7. Связать — Timeweb

- [ ] `TELEGRAM_API_BASE` = адрес Worker
- [ ] `TELEGRAM_WEBHOOK_BASE` = тот же адрес
- [ ] Передеплоить

### 8. Проверить, что живо

- [ ] `curl "https://telegram-proxy.<аккаунт>.workers.dev/bot<TOKEN>/getMe"` → `"ok":true`
- [ ] `<APP_URL>` → вход по паролю из шага 3
- [ ] `<APP_URL>/api/health` (в том же браузере, уже под входом) → 200 и
      `"database": { "checked": true, "ok": true }`. Без входа поле будет
      `"checked": false` — так и задумано: проба базы закрыта, чтобы чужие не
      выкачивали общий с Agentus лимит компьюта. Из терминала —
      `curl -H "Authorization: Bearer $CRON_SECRET" <APP_URL>/api/health`
- [ ] `<APP_URL>/settings` → красные точки только у переменных из раздела
      «Задел на будущее» (см. ниже)
- [ ] `<APP_URL>/api/dev/llm-ping` → отвечает, какой шлюз и модель обслужили
      запрос. Это же проверяет ключ Polza
- [ ] Поставить вебхук — в консоли браузера, будучи авторизованным:
      ```js
      fetch("/api/telegram/setup", { method: "POST" }).then(r => r.json()).then(console.log)
      ```
      Ожидается `"ok": true`
- [ ] Написать боту `/ping` → «понг» и версия сборки
- [ ] Написать боту обычное сообщение → отвечает Ася
- [ ] «напомни через 5 минут проверить бота» → через пять минут придёт
      напоминание с кнопками

### 9. Сразу после запуска

- [ ] **Заменить ключи, которые прошли через переписку**: Neon, Polza, токен
      бота. Это правка переменных в Timeweb и Neon, кода не касается
- [ ] Через сутки: сверить таблицу `LlmUsage` с реальными ценами в
      `src/core/llm/pricing.ts` — оценка стоимости там приблизительная

## Резервные копии — этого в системе нет

В репозитории **нет ни кода, ни процедуры резервного копирования**, хотя
`PLAN.md` считает их защитой от ошибок в личных финансах. Пока в базе только
тестовые данные, это терпимо; после первого импорта настоящей выписки —
уже нет.

- [ ] Включить резервное копирование на стороне Neon и узнать глубину хранения
      своего тарифа
- [ ] Хотя бы раз отрепетировать восстановление и засечь время

## Чего нет, хотя переменные существуют

Эти переменные описаны в `.env.example` и показываются на экране настроек, но
**не читаются ни одной строкой кода**. Задать их можно — не включится ничего.

| Переменная | Состояние |
|---|---|
| `STT_PROVIDER`, `STT_MODEL` | Распознавание речи **не написано**. Бот на голосовое сообщение честно отвечает, что не поддерживает |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | **Готово.** Задайте ключи — синк начнёт забирать поступления каждые 6 часов |
| `YANDEX_GEO_API_KEY`, `DGIS_API_KEY` | Фаза 3, модуля продаж ещё нет |
| `INBOUND_LEAD_SECRET` | Фаза 3, эндпоинта приёма заявок ещё нет |

## Две вещи, о которых стоит знать

**Резерва у модели нет.** Блок переменных в `DEPLOY.md` ставит
`LLM_GATEWAYS=polza`. Каскад на два шлюза написан и работает, но со вторым
ключом. Пока ключ один: перестанет отвечать Polza — перестанет работать весь
ИИ, включая утренний бриф и чат. Лечится добавлением ключа ProxyAPI и
`LLM_GATEWAYS=polza,proxyapi`.

**`TRUSTED_PROXY_HOPS`.** Сколько прокси перед приложением считать доверенными
при разборе `x-forwarded-for` — от этого зависит, по чьему адресу считается
лимит попыток входа. По умолчанию `1`, и это верно для Timeweb напрямую.
**Если когда-нибудь поставите перед приложением Cloudflare — увеличьте на
единицу**, иначе лимит начнёт считаться по адресу прокси, то есть перестанет
защищать.

## Если что-то не так

| Симптом | Где смотреть |
|---|---|
| `/api/health` → `database.ok: false` | Строки подключения Neon; не кончились ли компьют-часы Neon |
| Контейнер не стартует, в логах про пул | `DIRECT_URL` указывает на `-pooler`; нужна строка без него |
| Бот молчит | `GET /api/telegram/setup` → поле `last_error_message`; проверить `TELEGRAM_OWNER_CHAT_ID` |
| В логах `telegram.webhook_secret_missing` | Не задан `TELEGRAM_WEBHOOK_SECRET` — вебхук закрыт намеренно |
| Прокси отдаёт 502 | Worker не задеплоен или не задана переменная `ORIGIN` |
| `llm-ping` → 503 | Ключ Polza не работает или кончились деньги на балансе |
| В логах `llm.budget_exceeded_blocked` | Достигнут `LLM_DAILY_BUDGET_RUB`; обнуляется в полночь по Москве |
| Кроны отвечают 503 | Не задан `CRON_SECRET` — тогда не работает вообще ничего по расписанию |
| Ответы бота дублируются | Дедуп открылся из-за недоступной базы — смотреть `/api/health` |

# Запуск в прод — пошагово

Порядок важен: приложение узнаёт свой адрес только после создания в Timeweb, а
Worker узнаёт адрес приложения от вас. Поэтому шаги 3 и 4 идут парой.

Всё занимает около получаса. Собственный домен **не нужен** — ни для
приложения, ни для Telegram.

Короткий список галочек без объяснений — [`OWNER-CHECKLIST.md`](./OWNER-CHECKLIST.md).

---

## 1. Neon (база)

В SQL-консоли проекта:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

Без `vector` не применится миграция векторной памяти, без `pg_trgm` не
заработает поиск по фактам при опечатках.

**Про scale-to-zero.** На бесплатном тарифе Neon его отключить нельзя — база
засыпает через 5 минут простоя, и первый запрос после сна ждёт пробуждения
(обычно меньше секунды). Система с этим считается в двух местах: крон
напоминаний держит ближайший срок в памяти и будит базу только когда он
наступил, а проба живости контейнера ходит на `/api/health/live` — роут без
базы. Второе не мелочь: пока проба ходила на `/api/health`, она одна давала
2880 запросов в сутки, и компьют не засыпал никогда.

`/api/health` остаётся для диагностики руками — он показывает
`checks.database` и потому в базу ходит. Дёргать его по таймеру не надо: лимит
бесплатного тарифа общий на весь аккаунт Neon и выбирается одинаково что
полезной работой, что пробами.

Если тариф платный — scale-to-zero стоит выключить в Settings → Compute,
задержки пробуждения исчезнут.

Скопируйте две строки подключения (Connection string):
- **pooled** — хост с суффиксом `-pooler`. Допишите в конец `&pgbouncer=true`.
- **direct** — тот же хост без `-pooler`.

Обе нужны: приложение ходит через пул, миграции — напрямую (пул не пропускает
блокировку, которую берёт Prisma).

## 2. Пароль для входа

Локально, в каталоге проекта:

```
npm run hash:password -- 'ваш-пароль'
```

Команда напечатает строку `OWNER_PASSWORD_HASH=$argon2id$...`. В переменные
идёт **хэш**, сам пароль нигде не сохраняется.

Ещё три секрета — любой генератор:

```
openssl rand -base64 48   # AUTH_SECRET
openssl rand -hex 32      # CRON_SECRET
openssl rand -hex 32      # TELEGRAM_WEBHOOK_SECRET
```

## 3. Timeweb (приложение)

Создать приложение типа **Docker** из этого репозитория: ветка `main`,
Dockerfile в корне, порт `3000`.

Переменные окружения — вставить целиком, подставив свои значения:

```
DATABASE_URL=<pooled-строка Neon с &pgbouncer=true>
DIRECT_URL=<direct-строка Neon>
AUTH_SECRET=<openssl rand -base64 48>
OWNER_PASSWORD_HASH=<из шага 2>
CRON_SECRET=<openssl rand -hex 32>
APP_URL=<технический адрес приложения от Timeweb>
LLM_GATEWAYS=polza
POLZA_API_KEY=<ключ polza.ai>
LLM_DAILY_BUDGET_RUB=500
TELEGRAM_BOT_TOKEN=<токен от @BotFather>
TELEGRAM_OWNER_CHAT_ID=<ваш chat_id от @userinfobot>
TELEGRAM_WEBHOOK_SECRET=<openssl rand -hex 32>
TELEGRAM_API_BASE=<адрес Worker из шага 4>
TELEGRAM_WEBHOOK_BASE=<адрес Worker из шага 4>
```

Два последних значения появятся на шаге 4 — их можно дописать после.

`LLM_GATEWAYS=polza` означает **один шлюз без резерва**: перестанет отвечать
Polza — перестанет работать весь ИИ, включая утренний бриф. Каскад на два
шлюза написан и включается вторым ключом:
`LLM_GATEWAYS=polza,proxyapi` плюс `PROXYAPI_API_KEY`.

Миграции применит сам контейнер при первом старте. Отдельно ничего запускать
не нужно.

## 4. Cloudflare Worker (Telegram)

**Домен не нужен**: Cloudflare выдаёт каждому Worker бесплатный адрес
`<имя>.<аккаунт>.workers.dev`.

Без этого прокси бот не сможет отправлять сообщения вообще — прямой
`api.telegram.org` из Timeweb заблокирован. Это не про скорость, а про
работоспособность.

Пошаговая инструкция и готовый скрипт — в
[`infra/cloudflare-worker/`](../infra/cloudflare-worker/README.md). Коротко:
создать Worker, вставить `worker.js`, задать переменную `ORIGIN` = адрес
приложения из шага 3, забрать выданный адрес `*.workers.dev` и вписать его в
`TELEGRAM_API_BASE` и `TELEGRAM_WEBHOOK_BASE`.

## 5. Первый запуск

1. **Здоровье системы.** Откройте `<APP_URL>/api/health` — ожидается `200`,
   `"database": { "ok": true }`. Если `ok: false` — база не поднялась,
   смотрите текст ошибки в поле рядом.
2. **Вход.** Откройте `<APP_URL>`, введите пароль из шага 2.
3. **Главный экран** показывает состояние настроек: подключена ли база, есть ли
   ключи LLM, настроен ли Telegram. Красная точка = переменная не задана.
4. **Проверка модели.** `<APP_URL>/api/dev/llm-ping` (из-под входа) —
   отвечает, какой шлюз и какая модель обслужили запрос. Это же покажет,
   работает ли ключ Polza.
5. **Вебхук Telegram.** В браузере, будучи авторизованным, выполните в консоли:
   ```js
   fetch("/api/telegram/setup", { method: "POST" }).then(r => r.json()).then(console.log)
   ```
   Ожидается `"ok": true`. Проверить состояние позже — `GET` того же адреса.
6. **Живая проверка бота.** Напишите боту `/ping` — ответит «понг» и версию
   сборки. Затем обычное сообщение — ответит Ася. Затем «напомни через 5 минут
   проверить бота» — через пять минут придёт напоминание с кнопками.

## Что заработает сразу

| Когда (местное, UTC+5) | Что |
|---|---|
| каждую минуту | доставка напоминаний |
| 07:30 | утренний бриф |
| 21:30 | вечерний чек-ин с кнопками |
| 22:00 | ночная сводка дня и пополнение памяти |
| каждые 10 минут | пульс системы в ленту событий |
| 06:30 | чистка журнала дедупликации вебхуков |
| 06:45 | чистка сырых файлов импортированных выписок |
| 04:15, 10:15, 16:15, 22:15 | синк поступлений ЮKassa (если заданы ключи) |
| 23:00 | пересчёт финансовых наблюдений |

Расписание живёт в `scripts/start-container.mjs` (в UTC) — планировщик
контейнера, потому что кроны хостинга на Timeweb недоступны. При смене
`OWNER_TZ` его надо сдвинуть вручную: переменная меняет только то, как режутся
сутки, но не то, в какой час UTC срабатывает джоба.

## Если что-то не так

| Симптом | Где смотреть |
|---|---|
| `/api/health` отдаёт `database.ok: false` | Строки подключения Neon; не исчерпан ли лимит компьют-часов |
| В логах `Миграции не проходят через пул` | `DIRECT_URL` указывает на `-pooler`; нужна строка без него |
| Бот молчит | `GET /api/telegram/setup` → поле `last_error_message`; проверьте `TELEGRAM_OWNER_CHAT_ID` |
| В логах `telegram.webhook_secret_missing` | Не задан `TELEGRAM_WEBHOOK_SECRET` — вебхук закрыт намеренно |
| `llm-ping` отвечает 503 | Ключ Polza не работает или кончились деньги на балансе |
| В логах `llm.budget_exceeded_blocked` | Достигнут `LLM_DAILY_BUDGET_RUB` за сутки; лимит обнуляется в полночь по Москве |
| Кроны отвечают 503 | Не задан `CRON_SECRET` |

Расходы на модель видны в таблице `LlmUsage` — по ней же стоит сверить
реальные цены с оценкой в `src/core/llm/pricing.ts` после первых суток работы.

## После настройки

Переданные в переписке ключи (Neon, Polza, токен бота) стоит заменить: они
прошли через историю сообщений. Замена — это правка переменных в Timeweb и
Neon, кода не касается.
